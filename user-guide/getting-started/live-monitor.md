# 开启实时监测

在 Kimi Code / Qwen Code 里继续干活，新对话自动出现在 viblogy 的时间线上——无需导出、无需拖拽。

::: tip 前提
实时监测在应用运行时工作：viblogy 开着，才会同步。
:::

## 开启 Kimi 实时监测

1. 打开「设置 → Kimi CLI 实时会话监测」；
2. 打开「启用实时监测」开关。

默认监测 `~/.kimi-code/sessions/`。如果提示「未检测到 Kimi CLI 会话目录」，说明该目录不存在——可以打开一次 Kimi Code，或在下方「监测路径」中填写实际位置（支持绝对路径或 `~/` 开头的路径；留空保存即恢复默认）。

相关选项：

- **监测时间范围**：默认仅监测最近 24 小时内有内容更新的会话（可选 1 / 12 / 24 小时）；
- **扫描间隔**：默认 5 分钟（可选 1 分钟～8 小时）。间隔越短，新内容发现越快，系统资源消耗也越高。

## 开启 Qwen Code 实时监测

1. 打开「设置 → Qwen Code 实时会话监测」；
2. 打开「启用 Qwen Code 监测」开关。

默认监测 `~/.qwen/projects/<项目>/chats/`；「监测路径」中填写的是 projects 根目录。

两个监测的开关**相互独立**：可以只开其中一个；关闭任意一个，已导入的会话都不受影响。

## 同步是怎么发生的

- 开启后，CLI 中正在进行的会话会被自动发现，新增的对话内容**增量同步**到时间线，边聊边入库；
- 想立即同步一次：时间线顶部工具栏有刷新按钮（任一监测开启时显示），点击即刻执行一次完整扫描，扫描中按钮显示「正在扫描...」；
- 同一会话中由子代理（subagent）产生的内容：Kimi 侧会并入对应会话一起记录（不单独成会话）；Qwen 侧的子代理会话不采集。

## 注意事项

- 同时开启实时监测与文件夹监测、且两者指向重叠内容时，应用会提示可能重复导入，并提供一键关闭文件夹监测的选项；
- 关闭监测开关只是暂停同步，已同步的会话全部保留；
- 除了实时监测，也可以配置监测文件夹自动导入 `.md` 导出文件（见「导入与整理」章节，撰写中）。

## 常见问题

**开启了监测，但新会话一直不出现？**
依次检查：CLI 是否正在运行且会话位于被监测的目录下；点击时间线顶部的刷新按钮立即扫描一次；「监测时间范围」是否过小（例如最近有更新的会话超出了所选范围）。

**临时不想被监测？**
关掉对应开关即可，历史数据不受影响，随时可重新开启。
